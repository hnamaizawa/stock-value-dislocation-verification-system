## 初回同期と429について

全銘柄の約1年分の日足と約3年分の決算開示を取得するため、初回同期は多数のAPI要求を伴います。契約プランによっては長時間かかります。

0.3.4でも次の取得動作を維持します。

1. 最初から要求間隔13秒で保守的に直列取得
2. 429を受けたら既定で65秒待機
3. 以後は要求間隔を20秒以上へ切り替え
4. 完了した日を即座にcacheへ保存
5. 上限回数後も429が続いた場合は停止するが、再実行すると未取得日から再開
6. 契約期間外の日付は、APIが返した契約開始日・終了日へ自動調整

取得中は黒い画面へ進捗が表示されます。同じ更新ボタンを繰り返し押す必要はありません。

設定は `config/real_data.yaml` の `providers.jquants.rate_limit` で変更できます。レート上限は契約プランや運用状況によって異なるため、短く変更しすぎないでください。

## 実データで取得するもの

- 上場銘柄一覧: `ClientV2.get_list`
- 株価日足: `ClientV2.get_eq_bars_daily(date_yyyymmdd=...)` の直列・再開可能取得
- 決算サマリー: `ClientV2.get_fin_summary_cursor(date_yyyymmdd=...)` の直列・再開可能取得

- 任意の適時開示検索: `ClientV2.get_td_list`（TDnetアドオン契約時）

### v0.6.12: 外的要因レビューと最新市場鮮度

外的要因レビューの記述項目は任意です。各欄には入力例のプレースホルダーとガイドラインがあり、人が内容を確認して `approved` に保存したこと自体をレビュー承認として扱います。`pending`、`rejected`、未保存、破損レビューは注文直前プレビューをブロックします。

個別銘柄の注文直前プレビューにおける市場データ鮮度は、Yahoo Finance系（yfinance経由）の日足最終取引日で判定します。Yahooデータは最新市場確認・トレンド用途に限定し、J-Quantsのpoint-in-time定量スコアや財務スナップショットは変更しません。Yahoo取得不能または鮮度超過なら安全側に倒して注文直前プレビューをブロックし、SBI証券での現在値・板・最新ニュースの人手確認も引き続き必須です。
