# 自動ルール学習（v0.6.54）

## 目的

「履歴・実績検証」に蓄積された point-in-time の定量分析履歴と、すでにローカル保存されている株価履歴から、
`value_dislocation`（外的要因で株価が下がっている可能性がある銘柄）の**定量抽出条件**を少しずつ改善します。

これは将来リターンを保証する機械学習ではありません。過去の関連性を使ったルール校正であり、過学習・市場環境変化・サンプル偏りは残ります。

## 自動改善の対象

自動変更できるのは次の定量条件だけです。

- 自己資本比率
- 3年営業CFの黒字比率
- 3年売上CAGR
- 営業利益率
- 会社予想営業利益の許容悪化率
- 52週高値からの下落率
- 6か月市場比劣後率
- 定量スコア下限

以下は**自動変更しません**。

- 外的要因らしさ (`minimum_externality`)
- 一時性確率 (`minimum_temporary_probability`)
- カタリスト確率 (`minimum_catalyst_probability`)
- 外的要因レビューの `approved / pending / rejected`
- 注文前の人手確認
- SBI証券への注文・ログイン関連

「外的要因だったか」は一次資料を含む人の確認が必要であり、履歴リターンだけから自動的に事実認定しません。

## 学習データ

自動学習はネットワークアクセスを行いません。

利用するのは次だけです。

1. `data/history/analysis/*.csv.gz` の point-in-time 日次分析履歴
2. `config/real_data.yaml` の `paths.prices` が指す、すでに取得済みのローカル株価

分析日の `close` を入口価格として、ローカル株価から30/90/180日後のリターンを計算します。

同じ銘柄を毎日観測した結果が統計を水増ししないよう、同一銘柄は標準30日以上あけたイベントに間引きます。

## ◎☆だけで学習しない理由

◎☆だけで学習すると、現在の条件で既に拾えた銘柄しか観測できません。
条件を少し緩めたときに拾えたはずの「良い見逃し銘柄」を評価できないためです。

そこで、日次分析履歴のうち

- 現在 `selected_for_review=True` の銘柄
- その条件だけで落ちた near-miss 銘柄

を使い、**一度に1条件だけ**変えた場合の結果を比較します。

## 過学習を抑えるゲート

標準設定は次です。

- 90日後リターンを主評価
- 成熟イベント40件以上になるまで変更禁止
- 時系列の前70%を学習、後30%を検証に使用
- 学習側20件以上、検証側10件以上
- 検証側の平均90日リターンが現行条件より **+2ポイント以上** 改善
- 検証側のプラス率を悪化させない
- 現行条件の35%以上の候補数を維持
- 30日・180日の確認指標を大きく悪化させない
- 1回の更新で変更する条件は1つだけ
- 自動適用後30日は次の自動変更を行わない
- 閾値ごとに探索可能な上下限と刻み幅を固定

データが足りない場合、改善が検証期間で再現しない場合は**何も変更しません**。

## 自動適用とロールバック

`config/real_data.yaml` の標準設定では次を有効にします。

```yaml
rule_learning:
  enabled: true
  auto_apply: true
```

自動学習は `config/real_data.yaml` 自体を書き換えません。
採用された条件は実行時オーバーレイとして次へ保存します。

```text
data/history/rule_learning/active_rules.json
```

学習状態:

```text
data/history/rule_learning/state.json
```

変更履歴:

```text
data/history/rule_learning/audit.jsonl
```

これらはローカル実行時データでありGit管理対象外です。

元へ戻す場合は `active_rules.json` を削除するか、`clear_active_rule_overrides()` を使います。ソースYAMLが常にベースラインなので、Gitの設定ファイルを書き戻す必要はありません。

## 実行タイミング

`load_config(config/real_data.yaml)` のときに履歴ファイル署名を確認します。
履歴・ローカル株価・基準設定が前回と同じなら再学習しません。
変化があった場合だけ評価し、採用条件を満たした改善があれば自動適用します。

重要: **条件変更や自動学習を理由にJ-Quants/Yahooを取得しません。** データ取得は既存のデータ更新フローだけが担当します。

## 解釈上の注意

- 過去の相関であり因果関係ではありません。
- 市場レジームが変わると過去に良かった条件が効かなくなる可能性があります。
- 履歴初期はサンプルが少ないため、自動適用されないことが正常です。
- 外的要因レビュー、人による投資仮説の確認、注文前確認は引き続き必要です。
